A scoring request, start to finish

The path behind the Model Lab

  1. Validate — Pydantic enforces 9 required fields and non-negative numbers.
  2. Frame — predict_lead() checks types, finiteness and ranges.
  3. Transform — median imputation, standardization, one-hot encoding inside the saved pipeline.
  4. Score — logistic regression returns a probability in [0, 1].
  5. Decide — probabilities at or above 0.75 become "Likely to Convert".
  6. Return — probability, label and threshold as JSON.
This website reproduces steps 3–5 in JavaScript from the exported pipeline parameters, so the demo works without a backend.

Dataset

Nine features, one binary target

data/raw/sales_leads_raw.csv — 5,000 synthetic B2B leads, 0 missing values, 0 duplicate rows, 82.68% converted.

Preparation

What the pipeline does to the raw table

  • Numeric: median imputation, then standard scaling.
  • Categorical: most-frequent imputation, then one-hot encoding with unknown categories ignored.
  • Split: 64% train, 16% validation, 20% reserved test, stratified.
  • Selection: logistic regression chosen over dummy, random forest and gradient boosting candidates.
  • Threshold: tuned on validation macro F1, deployed at 0.75.
The CSV is generated, not observed. Performance here demonstrates a working pipeline; it says nothing about real conversion lift.

Intended use

  • Prioritising follow-up inside a sales team.
  • Explaining which behaviours correlate with conversion.
  • Demonstrating an end-to-end ML + RAG service.

Out of scope

  • Credit, pricing or hiring decisions.
  • Any decision without human review.
  • Claims of real-world causal impact.
  • Production traffic without auth, logging and drift monitoring.

Quickstart

Run the whole thing locally

Windows PowerShell commands; the same steps work with the equivalent shell syntax elsewhere.

1. Environment and services

PowerShell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

ollama pull llama3.2:1b
python scripts/ingest_knowledge.py

python scripts/run_api.py
python scripts/run_dashboard.py

API on :8000, dashboard on :8501. The dashboard reads DASHBOARD_API_URL.

2. Verify and rebuild the site

PowerShell
python scripts/check_stack.py
python -m pytest tests -q

# regenerate website data from the artifacts
python scripts/export_web_data.py

# preview the static site
python -m http.server 8080 --directory web

The site is plain HTML, CSS and JavaScript. It reads the JSON in web/assets/data, so re-export after changing the dataset, model or documents.

Deployment note: this website is deployed as static files. The FastAPI service and Ollama model are not exposed publicly — run them locally, or containerise the backend separately before exposing it.
Limitations

What would have to change for production

Data

Training data is synthetic and has no timestamps, so drift, seasonality and leakage risk are unmeasured. Replace it with verified CRM history before drawing conclusions.

Modelling

ROC-AUC of 0.659 leaves plenty of room. Segment-level performance and calibration are not evaluated, and the 0.75 threshold trades recall for precision.

Operations

No authentication, rate limiting, structured logging or monitoring. The LLM runs locally without guardrails beyond prompt instructions and human approval policy.
